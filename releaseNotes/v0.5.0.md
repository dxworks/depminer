Output is now split per tool, and nothing the instrument emits carries the host's filesystem layout any more.

* **One folder per tool.** `results/depminer/`, `results/syft/`, `results/trivy/` — asking for "the Syft SBOMs" is a folder now, not a guess at a filename suffix. **This changes the layout inside the results zip**: a consumer that globbed `results/*.json` needs to look one level deeper. Provenance of the mined manifests stays in `results/depminer/index.json`, which maps each copied file to its path under the target.
* **Host paths are stripped from everything that ships.** The emitted SBOMs already were; the manifests and lockfiles the jar copies out of the tree were not. NuGet's `project.assets.json` was the worst of it — it carries the absolute path of every `.csproj`, the NuGet package folder, and on a client machine the URL of their internal Artifactory or Azure Artifacts feed, credentials included. All of it went out verbatim, exit 0, with nothing said.
* **Credentials embedded in lockfile URLs are removed.** `https://user:token@nexus.corp/...` in a resolved URL is rewritten to drop the userinfo; the host itself stays, so the SBOM is still readable.
* **The scrub is verified, not trusted.** Every emitted file is read back and checked against the host paths themselves — a rule that matched only a prefix used to leave the rest of the layout in place while every call still succeeded.
* **`results/scrub-report.json`** — one shared file at the root, written on every run, listing any file that shipped despite failing verification. **Nothing is ever withheld or deleted**: every file the scan produced is emitted, in its best-effort scrubbed form, and one project failing does not fail the run. The report is the only record that some of those bytes are not clean, so an empty `flagged` list is the signal to look for. The leaked value is never written into it — only which class of rule matched, and how often.
* **Dev dependencies are included** in the Syft and Trivy SBOMs, matching what Black Duck reports: `SYFT_JAVASCRIPT_INCLUDE_DEV_DEPENDENCIES` for npm/yarn lockfiles, and Trivy's `--include-dev-deps` for the rest (npm/yarn/pnpm, composer, uv.lock dev groups, gradle). Lockfile parsing only — still no network.
* **A project whose dependencies are not resolved now says so.** Previously a `pom.xml` with a cold `~/.m2` produced a thin SBOM that looked like a complete one. The .NET preparation advice was wrong and has been corrected — see [Preparing Your Project](https://dxworks.org/depminer/prep-guide/).

Upgrading in place: the instrument clears the root of `results/` on its first run, so a folder left over from 0.4.0 does not ship alongside the new layout.

Pinned tool versions: Syft 1.46.0, Trivy 0.72.0.

Every lockfile the scan reads is now saved, and the sanitize pass no longer rewrites versions inside them.

* **Every manifest and lockfile Syft and Trivy read is now copied out.** `Cargo.lock`/`Cargo.toml`, `go.mod`/`go.sum`/`go.work`, `uv.lock`, `poetry.lock`, `pdm.lock`, `packages.lock.json`, `Directory.Packages.props`, `requirements*.txt`, `pnpm-workspace.yaml`, `npm-shrinkwrap.json`, `*.gradle.kts`, `libs.versions.toml`, `buildscript-gradle.lockfile` — with the manifest beside each lockfile. The Syft SBOM cannot say which packages are direct for npm/yarn/pnpm/rubygems, and carries no edges at all for composer, rubygems, go and gradle. The lockfiles do, and until now only some of them shipped.
* **Sanitize patterns no longer corrupt lockfiles.** The jdbc connection-string rule matched `spring-boot-jdbc:4.1.0=…` in a `gradle.lockfile` and replaced four dependency versions with `***REDACTED***`. Patterns now take an optional `scope: manifests`; 14 config-file rules stay off lockfiles, prefixed-token rules keep running there. The default is `scope: all`, so an existing `sanitize.yml` keeps its meaning. Lockfiles are recognised by their original name in `index.json`, so a renamed `package-lock-1.json` is still one. Any rewrite inside a lockfile is reported in `scrub-report.json` as `redacted-inside-lockfile` — rule and count, never the value.
* **Package-manager config files are never copied.** `.npmrc`, `.yarnrc*`, `nuget.config`, `pip.conf`, `.pypirc`, `settings.xml`, `gradle.properties` and dotenv files hold no dependency information, and are exactly where registry tokens live.
* **`results/depminer/skipped.json`** — every file that matched a pattern but did not ship, with its path and the reason.

Pinned tool versions: Syft 1.46.0, Trivy 0.72.0.
